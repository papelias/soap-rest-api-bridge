# Portfolio publication audit

Scope: the files proposed for publication, the locked Python 3.11 environment,
the current application, the saved evaluation evidence, README, and demo plan.
This is an MVP publication-readiness check, not production or security certification.

The workspace had no Git metadata or remote. A clean source copy was created in
a separate location, excluding `.env`, virtual environments, caches, build output,
and local agent metadata. It was installed and tested independently. This verifies
clean-source setup, **not a remote Git clone or unavailable commit history**.
The original workspace and private `.env` were retained. No commits were made.

## Runtime and artifact checks

- Python requirement is `>=3.11,<3.12`; application source also parsed under the
  Python 3.11 grammar. Locked dependency installation and runtime imports succeeded.
- Startup and `GET /health` succeeded with no model key, model IDs, or SOAP URL.
  Attempted upstream initialization was made to fail during that check, proving it
  was not needed. Health returned HTTP 200 and `{"status":"ok"}`.
- `POST /ask` without credentials returned the expected structured 503
  `nl_not_configured` response, not a stack trace.
- With only the public SOAP URL supplied and no Anthropic credentials, five live
  GETs returned HTTP 200: Japan capital (Tokyo), Philippine currency (PHP), German
  phone code (49), Canadian full information, and EUR country list containing DE.
  Both temporary server lifespans stopped cleanly.
- The catalog regenerated byte-for-byte offline from the checked-in public WSDL
  snapshot and its public base URI. Raw scalar/structured/list/fault XML fixtures
  exist and pass through Zeep's actual response parser in tests.
- Baseline and improved run artifacts, their gold dataset, and source snapshots
  remain preserved. Offline report reproduction does not imply deterministic live
  LLM answers or an unchanged future public service.
- No abandoned feature placeholders or unused imports were found in application
  source review. Package marker modules and defensive invariant checks were retained.
  `print` calls occur only in explicit catalog/live/eval CLIs; they are intended
  command output, not request-path debugging statements. No speculative framework
  or extra runtime dependency was added during publication cleanup.

## Commands used

Commands were run from the clean source root using the installed uv executable;
the command forms below omit its machine-specific installation location. Credentials
and service environment variables were removed for the offline check.

```sh
uv sync --frozen --python 3.11
uv --offline run --frozen pytest -q
uv --offline run --frozen pytest 'tests/test_ask.py::test_every_unapproved_catalog_operation_is_blocked_by_code[CountryFlag]' -q
```

Startup verification used a temporary Python driver around `uvicorn.Server`,
HTTPX requests, and a `finally` block that stopped the server. The first lifespan
had no upstream configuration; the second supplied the public WSDL for the five
SOAP-backed REST checks. No new Anthropic calls or live evaluation reruns were
needed for this publication audit.

The final scan covered 77 publication files and found no secret/path issues.
All 17 relative Markdown links, fenced JSON examples, and 13 PowerShell code
blocks passed their checks. The README's answer/provenance example exactly matches
the stored rerun. Current application source matches the `improved-01` source
snapshot; this milestone changed documentation, checkout rules, and tests rather
than measured runtime behavior. All 14 recorded run files were verified unchanged.

## Must-fix defects

**No unresolved publication blockers were found in the audited files.**

Issues fixed during preparation:

1. Old eval instructions targeted shipped, immutable run labels and would fail on
   a fresh copy. README/protocol now use unused labels and compare to the baseline.
2. Checkout line endings were not pinned despite raw-byte dataset/source hashes.
   `.gitattributes` now specifies LF.
3. Catalog and evaluation reproducibility needed a direct offline regression
   check. Three publication tests now regenerate/verify the shipped artifacts.

The three recorded application failures were **not fixed or hidden** by this
documentation milestone: two answer-generation failures and incomplete handling
of a two-country comparison. The README reports them and makes no claim of perfect
end-to-end reliability.

## Optional improvements before portfolio publication

- Once a hosted repository exists, repeat the setup check from an actual remote
  clone and scan its history. That operation could not be tested here.
- Exercise Linux/macOS before advertising tested support for those platforms.
- Choose an explicit repository license; none was selected on the author's behalf.
- Record the demo and add a screenshot if useful; keep the key/configuration off
  screen and distinguish any recorded result from a live request.

Before any production proposal, resolve the recorded contract failures, expand
repeated evaluations, validate source quality and transport, and establish access,
privacy, operational ownership, and service-level requirements with the client.
Those are future work, not completed production capabilities.
